dotfiles

One-line shell bootstrap with a custom prompt, essential tools, and handy aliases for macOS, Linux, Windows and OpenWrt. Works offline too.

~/.zshlocal

Install

Run this single command. It downloads the config, sources it from both ~/.zshrc and ~/.bashrc, and auto-detects your shell and package manager: Homebrew, apt, dnf or yum.

one-line installer
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/zshlocal -o ~/.zshlocal && echo '[ -f ~/.zshlocal ] && source ~/.zshlocal' >> ~/.zshrc && echo '[ -f ~/.zshlocal ] && source ~/.zshlocal' >> ~/.bashrc && source ~/.zshlocal
zsh only
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/zshlocal -o ~/.zshlocal && echo '[ -f ~/.zshlocal ] && source ~/.zshlocal' >> ~/.zshrc && source ~/.zshlocal
bash only
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/zshlocal -o ~/.zshlocal && echo '[ -f ~/.zshlocal ] && source ~/.zshlocal' >> ~/.bashrc && source ~/.zshlocal
update
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/zshlocal -o ~/.zshlocal && source ~/.zshlocal

Windows

Three shells, three files. PowerShell gets the full prompt, Command Prompt gets what cmd is able to draw, and WSL is Linux, so it takes the same zshlocal as everything else.

PowerShell

Windows PowerShell 5.1 and PowerShell 7, and pwsh on macOS and Linux. Same two-line prompt with git branch, duration and status. PowerShell already uses gc, gl, gp and gcm for its own commands, so those four are gcv, gcmsg, gpull and gpush here.

powershell: install
iwr https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/profile.ps1 -OutFile "$HOME/.pslocal.ps1" -UseBasicParsing; if (!(Test-Path $PROFILE)) { New-Item -Force -ItemType File $PROFILE | Out-Null }; Add-Content $PROFILE '. "$HOME/.pslocal.ps1"'; . "$HOME/.pslocal.ps1"
if windows says scripts are disabled (per user, no admin)
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
optional: install git, vim, fzf and friends (winget, else scoop, else choco)
Install-DotfilesTools

Command Prompt

A coloured user@host|path prompt and the aliases as doskey macros, on Windows 10 or later. cmd cannot run anything while it draws its prompt, so there is no git branch and no exit status there; type ec to see the last exit code, or add Clink if you want a branch. It runs from the AutoRun registry value, stays out of non-interactive cmd /c calls, and installs nothing. AutoRun holds one command and this replaces it, so look first with reg query "HKCU\Software\Microsoft\Command Processor" /v AutoRun.

command prompt: install
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/cmdlocal.cmd -o "%USERPROFILE%\cmdlocal.cmd" && reg add "HKCU\Software\Microsoft\Command Processor" /v AutoRun /t REG_SZ /d "\"%USERPROFILE%\cmdlocal.cmd\"" /f
command prompt: undo
reg delete "HKCU\Software\Microsoft\Command Processor" /v AutoRun /f

WSL

Run the normal installer inside your WSL distro. It also adds open (through wslview or Explorer), pbcopy and pbpaste when Windows interop is on, and needs no systemd.

wsl: install (run inside the distro)
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/zshlocal -o ~/.zshlocal && echo '[ -f ~/.zshlocal ] && source ~/.zshlocal' >> ~/.zshrc && echo '[ -f ~/.zshlocal ] && source ~/.zshlocal' >> ~/.bashrc && source ~/.zshlocal

Supported Systems

The package manager is detected for you. A package the system's repositories do not carry is skipped and named, never an error.

  • HomebrewmacOS. Homebrew itself is installed first if it is missing.zshlocal
  • aptDebian, Ubuntu and their relatives, including inside WSL.zshlocal
  • dnfFedora, RHEL, CentOS Stream, Rocky, Alma, Amazon Linux 2023. On RHEL-family systems htop, ncdu, rclone and a few others need EPEL.zshlocal
  • yumOlder RHEL and CentOS, Amazon Linux 2. Used when dnf is not there.zshlocal
  • opkgOpenWrt and other BusyBox systems with no zsh or bash. Plain POSIX sh, a handful of small packages (htop, tree, ncdu, tmux), and only when there is room for them.ashlocal
  • wingetWindows PowerShell 5.1 and PowerShell 7. Tools are installed only when you run Install-DotfilesTools; scoop, then choco, are used when winget is missing.profile.ps1
  • cmdCommand Prompt on Windows 10 or later. Prompt and aliases only, no packages.cmdlocal.cmd

Offline & Air-gapped

No network is fine. Before installing anything the bootstrap makes one check that takes a few seconds at most. If it fails, package installs are skipped, one line says so, and the prompt and aliases are set up with whatever tools are already there. It looks again a day later.

Turn the network off for good

Either of these skips the check and every package manager. Use ~/.ashlocal-offline for the ash flavour and ~/.pslocal-offline for PowerShell. ZSHLOCAL_OFFLINE=0 does the opposite and installs without checking.

offline, as a flag file
touch ~/.zshlocal-offline
offline, for one shell
ZSHLOCAL_OFFLINE=1 zsh -l

Carry it to an air-gapped machine

Build a bundle on a connected machine that matches the target (same distro release, same CPU), move the one file across, and unpack it. auto adds the packages for that machine's package manager; leave it off to pack the dotfiles alone.

1. connected machine: build zshlocal-bundle.tar.gz
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/bundle.sh | sh -s -- auto
2. air-gapped machine: unpack and install
tar -xzf zshlocal-bundle.tar.gz && sh zshlocal-bundle/install.sh
or point a shell at an unpacked bundle yourself
ZSHLOCAL_BUNDLE="$PWD/zshlocal-bundle" zsh -l

Build for a different machine

When the connected machine is not a twin of the target (a Mac or Ubuntu laptop building for a Rocky server, an arm64 box or a router), name the target as family:distro:release:arch. For apt, dnf and yum the packages are downloaded by the target's own package manager inside a container of that distro, so this needs Docker or Podman; without one the script stops and tells you, it never packs the wrong platform. OpenWrt needs no container: the .ipk files come straight from the release's package feed. Add --dry-run to see exactly what would run.

apt target (debian 12, arm64)
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/bundle.sh | sh -s -- --target apt:debian:12:arm64
dnf target (rocky 9, x86_64)
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/bundle.sh | sh -s -- --target dnf:rocky:9:x86_64
yum target (amazon linux 2, x86_64)
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/bundle.sh | sh -s -- --target yum:amzn:2:x86_64
opkg target (openwrt 23.05.3, exact release and architecture)
curl -fsSL https://raw.githubusercontent.com/blaineam/blaineam.github.io/main/dotfiles/bundle.sh | sh -s -- --target opkg:openwrt:23.05.3:aarch64_cortex-a53

What a bundle can and cannot do

  • No index, no resolving. Offline there is nothing to resolve dependencies against. Only what is inside the bundle can be installed, which is why it has to be built on a matching machine. A bundle from another release or CPU is refused unless you set ZSHLOCAL_BUNDLE_FORCE=1.
  • apt and dnf bundles hold the full dependency closure, so they are self-contained but large (hundreds of megabytes). They are installed with dpkg -i and dnf install ./*.rpm with every repository disabled.
  • yum (yumdownloader) and opkg (opkg download) only fetch dependencies the building machine does not already have, so the target needs at least the same base system.
  • Targets are recorded in the bundle and checked on the other side: a rocky 9 x86_64 bundle installs on Rocky 9.x x86_64 and nowhere else. Another CPU architecture runs under emulation, which is slow and needs qemu/binfmt on Linux (Docker Desktop has it built in). RHEL itself has no default image; pass --image rockylinux:9 or similar. For OpenWrt, names the feeds do not carry (libc, kernel modules) are assumed to be in the firmware already.
  • Windows has no package bundle. winget, scoop and choco cannot install from one offline, so the bundle carries profile.ps1 and cmdlocal.cmd and nothing more.
  • Homebrew has no offline mode. brew fetch saves bottles for one macOS version and CPU, Homebrew must already be installed on the target, and it may still reach for the network. Treat it as best effort.
