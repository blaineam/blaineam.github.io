Guide

Turn your gaming PC into your own AI server

A gaming PC sits idle most of the day with one of the fastest AI chips you own inside it. This guide sets it up as a private server that Ari Helper on your iPhone, iPad and Mac can use for chat, vision, code, pictures and video. When you sit down to play, the PC is yours again.

Before you start

You'll set up three free, open-source servers. Each one does a different job, and you only need the ones you want:

ServerWhat Ari uses it forIn Ari
OllamaChat, reading photos (vision) and writing codeSettings › Self-Hosted › Ollama
ComfyUIPictures and video clips, with full control over models and workflowsSettings › Self-Hosted › ComfyUI
LocalAI (optional)An all-in-one server for chat, pictures and clips behind one addressSettings › Self-Hosted › LocalAI

What you need:

  • Windows 11 (or an up-to-date Windows 10) on the gaming PC.
  • An NVIDIA graphics card with at least 12 GB of video memory. A 24 GB card (RTX 3090, 3090 Ti, 4090, 5090) runs the larger models and video comfortably.
  • A current NVIDIA Game Ready or Studio driver.
  • About 150 GB free on an SSD. Models are large; video models especially.
  • Ari Helper on your iPhone, iPad or Mac.
Privacy by design. Every server below listens only on the PC itself (127.0.0.1). The PC then shares them with your own devices over Tailscale, a private network that only devices signed in to your account can join. None of these servers has a password of its own, so never expose them to your home network or the internet. Ari's Fortress Mode treats Tailscale addresses as your own network, so all of this keeps working with Fortress Mode on.

1Join your devices with Tailscale

  1. Install Tailscale on the gaming PC from tailscale.com/download and sign in.
  2. Install Tailscale on your iPhone, iPad and Mac, and sign in with the same account.
  3. In the Tailscale admin console, open DNS and make sure MagicDNS is on.
  4. Find the PC's name in the Tailscale app. It looks like gaming-pc.tail1234.ts.net. You'll use it for every address in Ari below; this guide writes it as YOUR-PC.

Open Terminal (or PowerShell) on the PC for the commands in this guide. The tailscale command is available once Tailscale is installed.

2Ollama: chat, vision and code

  1. Download and run OllamaSetup.exe from ollama.com/download. Ollama starts with Windows and listens on 127.0.0.1:11434. Leave it that way: don't turn on any "expose to network" option and don't set OLLAMA_HOST to 0.0.0.0.
  2. So games get their video memory back quickly, make Ollama unload idle models after two minutes. Open Settings, search for environment variables, choose Edit environment variables for your account and add: 
    OLLAMA_KEEP_ALIVE = 2m
    Then quit Ollama from the system tray and start it again from the Start menu.
  3. Download some models. Good starting points for a 24 GB card (see ollama.com/library for newer ones; on a 12–16 GB card pick the smaller sizes): 
    ollama pull gemma3:27b         # general chat that can also read photos
ollama pull qwen2.5-coder:32b  # code
ollama pull qwen2.5vl:7b       # fast photo and document reading
  4. Share Ollama with your devices over Tailscale: 
    tailscale serve --bg --tcp 11434 tcp://127.0.0.1:11434
  5. In Ari, open Settings › Self-Hosted › Ollama, enter http://YOUR-PC:11434 and tap Validate Connection. Your models appear in the model menu.

3ComfyUI: pictures and video

Use Comfy Desktop, the official ComfyUI app. It sets up Python and the GPU libraries for you, so there's nothing to type.

Install

  1. Go to comfy.org/download, click Download Desktop and run the Windows installer.
  2. Open Comfy Desktop. On the Install ComfyUI on this PC screen, check that it detected your NVIDIA card, accept the terms and click Install. If it asks you to update the NVIDIA driver, update it.
  3. When it finishes, ComfyUI opens in its own window. In the Comfy Desktop sidebar, right-click your build and make sure Auto start is on, so ComfyUI starts whenever the app opens.
  4. Leave the build's Startup arguments without --listen and keep the default port, so ComfyUI stays on 127.0.0.1:8188. To check, open http://127.0.0.1:8188 in a browser on the PC. If it doesn't load, the build's Overview tab shows the port it's using: close whatever else is using 8188 and restart the build.

Add a picture model

Put a checkpoint (a single .safetensors model file) in %LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\models\checkpoints (paste that into File Explorer's address bar). If you chose a different folder, Desktop settings › Folders shows where it is. An SDXL checkpoint, or an FP8 "all-in-one" FLUX checkpoint, is a good first choice. Ari runs any checkpoint there directly: pick it in the model menu and ask for a picture. Attach a photo and Ari uses it as the starting point.

Ready-made video workflow (recommended)

This download makes short video clips from one workflow. Ask with words only and SDXL makes a still picture, then Wan 2.2 animates it. Attach a photo and Wan 2.2 animates your photo instead. Clips are H.264 MP4, about 5 seconds long.

Download ari-sdxl-video-workflow.zip, then right-click it and choose Extract All. Inside are:

  • sdxl-video-gen-ari-api.json: the file you import into Ari.
  • sdxl-video-gen-ari.json: the same workflow, to open and edit in ComfyUI.
  • ari_helper_nodes: a required ComfyUI add-on.
  • README.md: full notes on the workflow.
  1. Install the add-on. In the Comfy Desktop sidebar, right-click your build and choose Show in Explorer (or Show in folder). In that folder, open ComfyUI\custom_nodes and copy the whole ari_helper_nodes folder into it. It needs no extra Python packages. An add-on is code that runs on your PC, so only install ones you trust; this one is a few short files you can read first.
  2. Download the seven models (about 45 GB). Save each one under %LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\models in the folder shown, creating the folder if it isn't there. Keep the file names exactly as they are.
    FolderFile (click to download)Size
    checkpointssd_xl_base_1.0.safetensors6.9 GB
    diffusion_modelswan2.2_i2v_high_noise_14B_fp8_scaled.safetensors14.3 GB
    diffusion_modelswan2.2_i2v_low_noise_14B_fp8_scaled.safetensors14.3 GB
    loraswan2.2_i2v_lightx2v_4steps_lora_v1_high_noise.safetensors1.2 GB
    loraswan2.2_i2v_lightx2v_4steps_lora_v1_low_noise.safetensors1.2 GB
    text_encodersumt5_xxl_fp8_e4m3fn_scaled.safetensors6.7 GB
    vaewan_2.1_vae.safetensors0.25 GB
  3. Restart ComfyUI (right-click your build, then Restart). View logs should show [ari-cleanup] on.
  4. Test it on the PC. Drag sdxl-video-gen-ari.json onto the ComfyUI window and click Run. It uses the example values in the Ari Helper inputs group. The workflow was built on ComfyUI 0.46.0, so update ComfyUI if it reports missing nodes. If a model is reported missing, check its folder and file name.
  5. Add it to Ari. Open Settings › Self-Hosted › ComfyUI › Import workflow file and choose sdxl-video-gen-ari-api.json. Get the file to your iPhone, iPad or Mac first, for example with iCloud Drive. After you finish Connect Ari below, pick the workflow in the model menu.

Write separate picture and motion prompts

Put ||| between what the picture shows and how it moves:

a red fox in a snowy forest, wildlife photograph ||| the fox slowly turns its head as snow falls

Without |||, both parts get your whole prompt. With a photo attached, only the motion part is used. Don't type backslashes anywhere in this workflow; it already has its placeholders.

Choose the video shape

Videos start out square. Ari doesn't have a size setting for ComfyUI yet, so it asks for 1024×1024. This workflow turns that into a 960×960 video, and crops an attached photo to a square. For widescreen or portrait, set the size in the workflow as below.
  1. Open sdxl-video-gen-ari.json in ComfyUI and find the ARI width and ARI height boxes.
  2. In both, delete everything in from_ari so it's empty.
  3. Set each test_value: 832 by 480 for widescreen, or 480 by 832 for portrait. For about 720p, use 1280 by 720 (or 720 by 1280); it's slower and needs more memory.
  4. Choose Workflow › Export (API) and import the new file into Ari.

Edit it later

Edit sdxl-video-gen-ari.json, save it in ComfyUI, then Export (API) and import that file into Ari. Apart from width and height above, leave each from_ari box as it is so Ari can fill it in. A test_value is used when you run the workflow in ComfyUI, and also whenever Ari doesn't send that value.

  • Faster, or running out of memory: set SETTING: max video pixels to 399360. The default, 921600, is about 720p and is the largest size the workflow will make.
  • Clip length: change length on Image to video (81 frames). 81 frames is about 5 seconds.
  • Extra LoRAs: the three boxes marked Optional are turned off. Before turning one on (select it and press Ctrl+B), choose your own LoRA file in it. The file shown there is only a stand-in.

Cleanup after download

For videos requested by Ari, the add-on deletes the video, the photo you attached and the job's history (which holds your prompts) about a minute after the whole video downloads. Anything never downloaded is deleted after about an hour. Viewing or downloading the whole video from any device counts, as does using this workflow from another app that talks to ComfyUI. Runs you start in the ComfyUI window are kept. To keep Ari's videos on the PC too, change the Save MP4 box's filename_prefix so it doesn't start with ari-private/, then export and import again.

This is ordinary deletion, not secure erasure, and it doesn't reach backups or synced copies. The MP4 you receive can contain the workflow and your prompts; adding --disable-metadata to the build's startup arguments stops that for all your workflows. The README lists the other limits.

Or use your own workflow for video (and anything else)

  1. In ComfyUI, open Workflow › Browse Templates and pick a video template, such as one of the Wan 2.2 text-to-video or image-to-video templates. ComfyUI offers to download the models it needs.
  2. Run it once in ComfyUI to make sure it works on your card.
  3. Make sure the video node saves MP4 (H.264). Apple devices can't play WebM.
  4. Optional: to choose where your prompt goes, replace the text in that prompt box with \{\{prompt\}\}, backslashes included. ComfyUI treats plain braces in many text boxes as "pick one of these" and removes them when it exports; the backslashes keep them, and the exported file contains {{prompt}}. Do the same in each box that should receive your prompt. Ari also understands negative_prompt, seed, width, height and image written the same way. Add placeholders after your test run, because ComfyUI would send them to the model as they are. Without them, Ari finds the prompt box by itself.
  5. Choose Workflow › Export (API) and save the .json file somewhere your Apple devices can reach, like iCloud Drive.
  6. In Ari, Settings › Self-Hosted › ComfyUI › Import workflow file (or paste the file's text). Imported workflows appear in the ComfyUI model menu; ones that make video are labelled.

Connect Ari

  1. Share ComfyUI over Tailscale: 
    tailscale serve --bg --tcp 8188 tcp://127.0.0.1:8188
  2. In Ari, open Settings › Self-Hosted › ComfyUI, enter http://YOUR-PC:8188 and tap Validate Connection. Ari shows the graphics card it found and lists your checkpoints.
  3. Turn on Free GPU memory after each run if you want ComfyUI to hand the card back as soon as each picture or clip is done.

4LocalAI: optional all-in-one server

LocalAI puts chat, pictures and clips behind one address with a model gallery you install from in a browser. Its native Windows build only runs chat models, so for pictures and video it runs in Docker.

  1. Install Docker Desktop with the WSL 2 backend, and turn on Start Docker Desktop when you sign in.
  2. Start LocalAI with GPU support, published only on the PC itself: 
    docker run -d --name local-ai --restart unless-stopped --gpus all -p 127.0.0.1:8080:8080 localai/localai:latest-gpu-nvidia-cuda-12
    (Use the -cuda-13 image instead on a recent driver. See LocalAI's container guide to keep downloaded models in a folder that survives updates.)
  3. Open http://127.0.0.1:8080 on the PC and install models from the gallery: a picture model (a FLUX or SDXL entry), a video model if you want clips, and a chat model if you like.
  4. Share it over Tailscale: 
    tailscale serve --bg --tcp 8080 tcp://127.0.0.1:8080
  5. In Ari, open Settings › Self-Hosted › LocalAI, enter http://YOUR-PC:8080 and tap Validate Connection. Choose the picture or video model, and turn on This model makes video clips for video models (Ari guesses from the name). Tap Use LocalAI's chat models too to add its chat models to the model menu.

5Hand the GPU to your games automatically

A small watcher script does this for you. The moment a game starts, it stops Ollama, ComfyUI and LocalAI so the game gets all of the video memory. When you quit the game, the AI servers start again a few seconds later, ready for Ari.

  1. Download ai-game-mode.ps1 and save it in C:\AI.
  2. Open Comfy Desktop and leave it running while you install the script, so the script can note where the app is. Check that Auto start is on for your build (section 3).
  3. Open PowerShell in C:\AI and install it: 
    powershell -ExecutionPolicy Bypass -File .\ai-game-mode.ps1 -Install
    This adds a hidden task named AI Game Mode that runs whenever you sign in, and starts it now. It also opens Comfy Desktop for you whenever the AI servers should be running.
  4. Check what it sees: 
    powershell -ExecutionPolicy Bypass -File .\ai-game-mode.ps1 -Status

When a game starts, the script closes Comfy Desktop completely, which also stops ComfyUI. When you quit the game, it opens the app again and Auto start brings ComfyUI back; you can minimize the window. Save any workflow you're editing before you play, because closing the app this way discards unsaved changes.

How it knows you're playing

Anything running from a game library counts as a game: every Steam library, Epic, GOG, Xbox (XboxGames), EA, Ubisoft, Riot and Blizzard game folders are found automatically, on every drive. Launchers sitting in the tray don't count, so having Steam or the Epic launcher open won't pause anything.

  • A game it misses (installed somewhere unusual): add its program name to $ExtraGames at the top of the script, e.g. 'MyGame.exe'.
  • Something that isn't a game keeps the AI paused (a tool installed through Steam, for example): the log names whatever triggered the pause, so add that name to $IgnoreGames. The log is at %LOCALAPPDATA%\AIGameMode\ai-game-mode.log.
  • After editing the script, run -Install again to restart it.

Options

  • Stop or unload. By default the servers stop entirely while you play, so nothing can load a model in the middle of your game; Ari reports that the server isn't answering until you quit. Set $PauseMode = 'Unload' to keep them answering with their models unloaded instead (Comfy Desktop then stays open). Ari can then still use the PC mid-game, at the cost of some video memory while it does.
  • How fast it comes back. $ResumeSeconds (3 by default) is how long it waits after the last game exits, so a game that restarts itself doesn't bounce the servers.
  • By hand. -Pause frees the GPU now, -Resume brings the servers back, and -Uninstall removes the task.

Keep it reachable

  • Stay awake while you're away. In Settings › System › Power, set the PC not to sleep when plugged in, or Ari can't reach it.
  • Ollama and Docker Desktop start with Windows on their own, the watcher opens Comfy Desktop, and Tailscale's serve settings survive restarts.

Troubleshooting

Validate Connection fails

  • On the PC, check the server answers locally: open http://127.0.0.1:11434, :8188 or :8080 in a browser.
  • Run tailscale serve status on the PC and make sure the port is listed.
  • Make sure the iPhone or Mac has Tailscale connected, and that you used the full .ts.net name.

"Out of memory" or a very slow first run

The first run loads the model from disk, which can take a minute. If it fails with out of memory, close other GPU apps, use FP8 or smaller models, lower the resolution or number of frames, or run the watcher with -Pause to clear what's loaded.

Ari says the clip can't be played

Set the workflow's video node to save MP4 (H.264), export it again with Export (API), and re-import it in Ari.

The ready-made video workflow shows missing or red boxes

If the Ari boxes are missing, check that ari_helper_nodes is directly inside your build's ComfyUI\custom_nodes folder (not inside a second folder of the same name), restart ComfyUI and look for errors in View logs. For other boxes, update ComfyUI.

My videos are square

See Choose the video shape under the ready-made workflow.

Ari can't find the prompt in my workflow

Type \{\{prompt\}\}, backslashes included, into each text box that should receive the prompt, export again, and re-import. If the exported file shows only prompt in that box, the backslashes were missing.

Should I use --listen or open the firewall?

No. That shares the server with every device on your network, and none of these servers asks for a password. Tailscale gives your own devices access without that risk. If Windows asks whether to allow a server on public or private networks, choose Cancel.
